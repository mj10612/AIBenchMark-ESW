# Task: Power-Safe Dual-Slot Flash Update

Dual slots each hold up to256 bytes. Begin takes durable active slot0/1 and immutable caller image length1..256. Require every HAL callback, clear initialized on failed begin, choose inactive slot via1-active, compute CRC16 CCITT-FALSE (poly0x1021/init0xFFFF). Begin does no HAL I/O. State sequence ERASE -> WRITE -> VERIFY -> COMMIT -> DONE. Each step performs at most one HAL operation, writes/reads chunks<=64, increments offset only after success. Verify CRC incrementally over read-back bytes; no commit until complete matching CRC. COMMIT publishes target,CRC,length once via HAL atomic commit. Any HAL error enters ERROR and returns IO; CRC mismatch enters ERROR and returns CRC. Later ERROR steps return IO without HAL; DONE returns OK without HAL. Null/uninitialized step returns ARGUMENT. CRC(NULL,0)=0xFFFF and CRC(NULL,nonzero)=0. The HAL guarantees atomic durable commit and never changes active on failed commit; real bootloader must validate the durable record on reboot. A power loss before commit keeps the old active slot; volatile update state is discarded and begin can restart against the durable active slot. No on-device filesystem or physical flash model is claimed.

Implement `src/flash_update.c` using the public header. No allocation, host I/O, floating point, or unbounded loops. Caller owns all state and storage. The tests are public host fixtures, not hardware certification.
